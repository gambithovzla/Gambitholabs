# Playbook · Gambitho Labs

**Manual operativo para el equipo comercial · v1.0 · Mayo 2026**

---

## Cómo usar este documento

Este playbook está pensado para que puedas vender Gambitho Labs sin haber estado en ninguno de los proyectos anteriores. Cubre:

- **Quiénes somos** y por qué un cliente nos contrata
- **Qué vendemos** y a qué precio
- **A quién le vendemos** y cómo identificarlo
- **Cómo conducir una venta**, desde el primer mensaje hasta el cierre
- **Cómo manejar objeciones** y dudas comunes

Léelo entero una vez para tener el panorama. Después úsalo como referencia rápida durante tus llamadas. Las **partes 4 (Cómo vender)** y **5 (Objeciones)** son las que vas a abrir más seguido — están escritas con scripts que puedes leer casi literal.

> **Una regla básica:** todo lo que digas a un cliente debe ser cierto. Si no sabes la respuesta a algo, decir _"déjame consultarlo y te respondo en una hora"_ es siempre mejor que improvisar.

# Parte 1 · Conoce a Gambitho Labs

## 1.1 Quiénes somos

Gambitho Labs es un estudio de desarrollo de software a medida con base en Lima, Perú. Construimos sistemas web para negocios que necesitan dejar de pelear con plantillas, hojas de Excel o herramientas que no fueron pensadas para su operación.

Nuestra propuesta cabe en una línea: **"Tienes una idea. Nosotros la convertimos en un sistema real."**

Operamos bajo la marca **Gambitho Labs · Ideas → Systems → Results**. Lo que vendemos no es una página web bonita ni un PDF entregable: vendemos sistemas funcionando que el cliente y su equipo usan todos los días.

## 1.2 Nuestra promesa

Tres frases que resumen lo que hacemos y lo que **no** hacemos:

| Lo que NO hacemos | Lo que SÍ hacemos |
| --- | --- |
| Entregamos archivos | Entregamos sistemas funcionando |
| Diseñamos páginas | Construimos productos reales |
| Vendemos plantillas | Resolvemos el problema operativo |

Cuando termina el proyecto, el cliente tiene algo que su equipo usa todos los días. No un PDF en una carpeta, no una página estática que nadie revisa.

## 1.3 Cómo trabajamos (los 4 pasos)

| Paso | Qué hacemos | Tiempo típico |
| --- | --- | --- |
| **01 · Entendemos tu idea** | Reunión inicial, sin tecnicismos. Mapeamos el problema operativo real. | 1 sesión |
| **02 · Diseñamos la solución** | Definimos qué construir, qué no, en qué orden. Te lo presentamos en una propuesta clara. | 1–2 semanas |
| **03 · La construimos** | Iteramos en sprints cortos. El cliente ve avances reales, no slides. | 4–12 semanas |
| **04 · La ponemos a funcionar** | Deploy, capacitación al equipo, entrega de credenciales y manual. | 1 semana |

Total típico de un proyecto mediano: **6 a 14 semanas** desde la firma hasta el sistema en producción.

> **Nota para la vendedora:** un cliente que pregunta _"¿cuándo lo tienes listo?"_ en la primera llamada todavía no entendió el alcance. Tu trabajo es llevarlo del _"necesito una página"_ al _"necesito un sistema"_. Una vez que entiende eso, los plazos toman sentido.

# Parte 2 · Qué vendemos

## 2.1 Los cuatro frentes

Vendemos cuatro tipos de proyecto. La mayoría de clientes encajan en uno solo, pero algunos requieren combinaciones.

### 01 · Desarrollo web
Webs corporativas, landings de campaña y PWAs (apps web instalables) construidas para vender y escalar. No son plantillas. Son sitios construidos a medida para el caso de uso.

**Ejemplos típicos de cliente:**
- Salón de belleza que necesita reservas online
- Estudio jurídico que necesita captar leads calificados
- Restaurante que necesita carta digital + delivery propio

### 02 · Apps web y móviles
Aplicaciones que funcionan en cualquier dispositivo (computadora, tablet, celular) sin tener que descargar nada de la tienda. Tecnología PWA.

**Ejemplos típicos:**
- App de fidelización de clientes
- Sistema de pedidos para staff interno
- Herramienta de captura en campo (vendedores, técnicos, etc.)

### 03 · Sistemas y dashboards
Paneles internos para que el equipo del cliente tenga sus datos al alcance. Centralizan información que hoy vive en Excel, papel o múltiples herramientas.

**Ejemplos típicos:**
- Panel administrativo para gestión de clientes y citas
- Dashboard ejecutivo con métricas en tiempo real
- Sistema de inventario y caja para retail pequeño/mediano

### 04 · Automatización
Conectamos lo que el cliente ya usa (WhatsApp, correo, Google Sheets, sistemas de terceros) y eliminamos el trabajo manual repetitivo.

**Ejemplos típicos:**
- Confirmaciones automáticas por WhatsApp/correo
- Alertas internas cuando ocurren eventos críticos
- Reportes automáticos a fin de mes
- Conexión con SUNAT (facturación electrónica)

## 2.2 Modelo comercial

Toda relación con un cliente tiene **dos componentes económicos** y debes presentarlos juntos desde el primer minuto.

### Pago único de implementación
Cubre el desarrollo, las pruebas, el deploy y la capacitación inicial. Se paga generalmente:
- **50%** al firmar el inicio del proyecto
- **30%** en el hito intermedio (versión funcional para revisión)
- **20%** al entregar el sistema en producción

### Mensualidad de soporte y mantenimiento
Cubre el funcionamiento continuo del sistema:
- Hosting (servidores, dominio, certificados de seguridad)
- Actualizaciones de seguridad y mantenimiento del entorno
- Soporte técnico ante consultas o fallos
- 2 horas mensuales para ajustes menores de contenido o configuración
- Recuperación del servicio si hay caída (hasta 4 horas)
- Renovación anual del dominio

> **Cómo presentarlo al cliente:** _"El proyecto se paga una vez al construirlo. Después, hay una mensualidad pequeña que mantiene el sistema vivo, igual que cuando alquilas una oficina y pagas el agua, la luz y la conserjería para que siga operando."_

## 2.3 Rangos de precios

Los siguientes son **rangos referenciales en dólares estadounidenses (USD)** para el mercado peruano y latinoamericano. El precio final depende del alcance específico que se cierre con el cliente y lo confirma siempre el dueño/líder técnico.

> **⚠ Importante:** estos rangos son lo que cobramos a clientes de mercado, **no** a amigos o familiares. Si te dan presión por bajar precio, escalas al dueño antes de comprometerte. **Bajar precio sin autorización destruye el negocio.**

# Parte 3 · A quién le vendemos

## 3.1 Cliente ideal

Un cliente ideal de Gambitho Labs cumple **al menos 3 de estas señales**:

- ✅ Tiene un negocio activo (no es un proyecto-idea sin facturar todavía)
- ✅ Su operación corre hoy en Excel, WhatsApp, papel o herramientas dispersas
- ✅ Tiene clientes recurrentes o flujo constante (no eventos one-off)
- ✅ Puede invertir mínimo $3,000 USD en el proyecto inicial
- ✅ Entiende que el software cuesta y no espera _"lo mismo de Wix por $50"_
- ✅ Está dispuesto a pagar una mensualidad de soporte
- ✅ Tiene a alguien en su equipo que va a usar el sistema todos los días

### Sectores donde tenemos experiencia o ajuste natural

| Sector | Tipo de proyecto típico |
| --- | --- |
| Estética y belleza | Reservas + admin + caja (caso JF Studio) |
| Clínicas y consultorios | Agenda médica + historia clínica + recordatorios |
| Estudios profesionales (jurídico, contable, arquitectura) | Web institucional + portal de clientes |
| Restaurantes y cafés | Carta digital + delivery propio + reservas |
| Inmobiliarias pequeñas y medianas | Catálogo + gestión de leads + visitas agendadas |
| Coaches, terapeutas, profesores particulares | Reservas + pagos + recordatorios |
| Negocios deportivos / gimnasios | Inscripciones + clases + control de acceso |
| Análisis de datos y SaaS de nicho | Plataformas con dashboards (caso HEXA) |

## 3.2 Cuándo NO vender

Es tan importante calificar al cliente como reconocer cuándo no es un buen fit. Si lo identificas a tiempo, ahorras horas de tu propio tiempo y evitas un mal cliente que después se queja.

**No somos opción cuando:**

- ❌ Quieren un e-commerce simple (Shopify lo hace mejor y más barato).
- ❌ Quieren solo un blog (WordPress lo hace mejor).
- ❌ Tienen presupuesto inferior a $1,500 USD para todo el proyecto.
- ❌ _"Lo necesitan para mañana"_ — los proyectos serios toman mínimo 4 semanas.
- ❌ No tienen claro su modelo de negocio. (Primero validan idea, después contratan software.)
- ❌ Esperan que les regalemos hosting eterno sin mensualidad.
- ❌ Vienen con una propuesta competidora muy barata y solo quieren que igualemos. (Ese cliente nunca cierra y siempre cuestiona.)

> **Cómo decir que no con elegancia:**
>
> _"Por lo que me cuentas, tu proyecto encaja mejor con [Shopify / WordPress / un freelancer junior]. Nosotros nos especializamos en sistemas a medida y arrancamos en $X,XXX. Te puedo recomendar a alguien que sí trabaja en tu rango si quieres."_
>
> Esto te posiciona como honesta y abre la puerta a referidos futuros.

# Parte 4 · Cómo vender

## 4.1 Elevator pitch (30 segundos)

> _"Gambitho Labs construye sistemas web a medida para negocios que ya operan y quieren dejar de pelear con plantillas y hojas de Excel. No vendemos páginas bonitas: entregamos sistemas funcionando, integrados con la operación diaria del cliente. Por ejemplo, para Johanna Figueredo Studio entregamos su web pública más un panel administrativo completo: reservas, agenda, caja, inventario, cumpleaños y correos automáticos, todo bajo el dominio del salón. Si tu negocio tiene operación recurrente y aún corre en Excel o WhatsApp, te conviene conversar con nosotros."_

**Cuándo usarlo:** primer contacto en frío (WhatsApp, correo, evento), o cuando alguien te pregunta _"¿a qué se dedican?"_.

## 4.2 Pitch extendido (2–3 minutos)

Estructura:

**1. El problema (30s):**
_"Muchos negocios crecen pegando soluciones sueltas: Excel para citas, WhatsApp para confirmar, papel para caja, otra herramienta para inventario. Llega un punto donde el dueño pierde 2-3 horas diarias coordinando y nada conversa entre sí."_

**2. Lo que hacemos (45s):**
_"Gambitho Labs construye un sistema único, a medida del negocio. Web pública para que el cliente final reserve o consulte, y un panel administrativo donde el equipo gestiona todo. No es una plantilla. Lo construimos en 8-12 semanas conversando con el dueño cada semana."_

**3. Caso concreto (45s):**
_"Te doy un ejemplo. Johanna Figueredo, salón de belleza en Miraflores. Antes: agenda en cuaderno, recordatorios manuales, caja en Excel. Hoy: johannafigueredo.com, sus clientas reservan online, reciben confirmación automática y un recordatorio 24 horas antes. El equipo entra al panel y ve la agenda del día con un código de color por estilista. Cierra caja en un clic. Exporta el reporte mensual en Excel para el contador."_

**4. El cierre (30s):**
_"Entregamos el sistema funcionando, capacitamos al equipo y nos quedamos con una mensualidad de soporte. Si te suena, nos sentamos 30 minutos contigo, te hago un par de preguntas y te paso una propuesta concreta sin compromiso. ¿Cuándo te queda bien?"_

## 4.3 Preguntas de calificación (las 8 que tienes que hacer siempre)

Estas preguntas son tu radar. Después de hacerlas, sabes si el lead es real, qué necesita y cuánto puede pagar.

1. **"Cuéntame del negocio: ¿qué hacen y desde cuándo?"** — distingue idea-papel de negocio operando.

2. **"¿Cómo gestionan hoy [el problema central]? ¿Excel, WhatsApp, papel, otro sistema?"** — identifica el pain real.

3. **"¿Cuántas personas en el equipo van a usar el sistema?"** — predice la complejidad de roles y permisos.

4. **"¿Cuántos clientes / citas / transacciones manejan al mes hoy?"** — predice volumen y nos dice si el negocio puede pagar.

5. **"¿Qué te llevó a buscar una solución ahora? ¿Qué pasaría si seguís igual otros 6 meses?"** — descubre la urgencia y el costo del no-hacer.

6. **"¿Tienen presupuesto definido o están explorando?"** — filtra leads tibios.

7. **"¿Quién toma la decisión final? ¿Conviene incluirlo en la próxima conversación?"** — evita perder el tiempo con quien no decide.

8. **"¿Para cuándo te gustaría tenerlo en producción?"** — calibra expectativas de tiempo.

> **Cómo procesarlas:** si el lead pasa al menos 5 de estas 8 con respuestas concretas, es un lead caliente. Pasa al pitch extendido y agenda reunión de descubrimiento. Si pasa menos de 5, probablemente está explorando — manda material y pide volver a hablar en 2-3 semanas.

## 4.4 Talking points por servicio

Argumentos clave que puedes adaptar según lo que el cliente diga que necesita.

### Si dice "necesito una página web"
- _"Una página web no soluciona problema operativo. Si tu equipo sigue gestionando todo afuera de la web, la web es solo un volante online. ¿Qué proceso del negocio te quita más tiempo?"_
- Pivotear hacia: web pública + panel administrativo (sistema completo).

### Si dice "necesito una app"
- _"Hoy el 90% de los casos se resuelven mejor con una PWA — que se instala desde el navegador y funciona como app, sin pasar por App Store ni Google Play. Eso te ahorra meses de aprobaciones y costos de tienda. ¿La app que necesitas es para clientes externos o para tu equipo interno?"_

### Si dice "necesito un dashboard"
- _"Perfecto, eso es nuestro fuerte. ¿De dónde vienen los datos hoy? ¿Tienen un sistema interno, varias hojas de Excel, una API de un proveedor?"_
- Probar el alcance: solo visualización vs sistema completo con captura.

### Si dice "necesito automatizar [X]"
- _"La automatización siempre se monta sobre algo que ya funciona. ¿Qué tienen hoy que pueda conectarse, y qué proceso querés automatizar específicamente?"_

## 4.5 Diferenciación frente a alternativas

| Alternativa | Cuándo es mejor que nosotros | Cuándo NO lo es |
| --- | --- | --- |
| **WordPress / Wix** | Sitio informativo simple, blog, presupuesto < $1,000 | Cualquier operación de negocio (reservas, caja, inventario, lógica propia) |
| **Shopify** | E-commerce puro, catálogo de productos físicos | Negocio de servicios, citas, suscripciones complejas |
| **Freelancer junior** ($500–1000) | Tarea muy puntual, sin necesidad de soporte ni estabilidad | Cualquier sistema operativo: el junior se pierde a los 2 meses |
| **Agencia grande** ($30k+) | Empresa grande con equipo TI propio que requiere certificaciones formales | PYMES y emprendedores: la agencia los ahoga en burocracia |
| **SaaS genérico** (Square, Calendly, etc.) | Necesidad muy estándar, cliente que no quiere personalización | Cuando el negocio tiene reglas particulares (horarios, productos, recetas, descuentos) |

# Parte 5 · Manejo de objeciones

Las 8 objeciones más comunes y cómo responderlas. Léelas antes de cada llamada importante.

## 5.1 "Es muy caro"

**Por qué la dicen:** no han comparado con su costo real de operar. Lo ven como gasto, no como inversión.

**Respuesta:**
> _"Te entiendo, es una decisión grande. Hagamos un cálculo rápido: si hoy [el dueño/recepcionista] gasta 2 horas diarias coordinando citas/cobros/inventario manualmente, eso son 40 horas al mes. Con un sueldo promedio en Lima de [$X/hora], son [$XX] al mes que estás pagando en tiempo. El sistema se paga solo en [X] meses, y después quedan los años de uso libre. La pregunta correcta no es '¿es caro?', es '¿cuánto me está costando hoy no tenerlo?'."_

**Si insiste:** pregúntale qué pieza del alcance se podría posponer a una segunda fase. Mejor dividir en fases que regalar precio.

## 5.2 "Mi sobrino / un amigo me lo hace gratis (o muy barato)"

**Por qué la dicen:** no diferencian _"tener algo"_ de _"tener algo que funciona y se mantiene"_.

**Respuesta:**
> _"Es una opción válida, y muchos clientes nuestros empezaron así. El problema típico llega a los 3-6 meses: el sobrino consigue trabajo, ya no responde, no documentó nada, y cuando algo falla nadie sabe arreglarlo. Te quedas con un sistema que funciona pero del que dependes de una persona específica. Lo que vendemos nosotros no es solo construir, es dejarte con un sistema documentado, con soporte, y con un equipo al que puedes escribirle a cualquier hora con la garantía de que respondemos. Si tu negocio depende del sistema, esa garantía vale el diferencial."_

## 5.3 "WordPress / Wix me sale más barato"

**Por qué la dicen:** comparan productos distintos.

**Respuesta:**
> _"Tienes razón, y para una página informativa WordPress o Wix son la mejor opción. Lo que nosotros construimos no es una página, es un sistema. ¿Tu negocio puede operar solo con una página informativa, o necesitas que la web procese reservas con tus reglas, registre cobros, controle inventario, mande recordatorios automáticos? Si solo necesitas presencia online, te recomiendo Wix de buena fe. Si necesitas operar el negocio desde la web, eso WordPress no lo hace y por eso existimos nosotros."_

## 5.4 "Ya tengo página web"

**Respuesta:**
> _"Perfecto, eso es un punto de partida. Cuéntame: tu página actual, ¿resuelve solo la presentación del negocio, o también la operación? Por ejemplo: ¿desde tu web hoy puedes ver cuántas citas tienes mañana, cuánto vendiste esta semana, cuáles son tus 5 clientes que más gastan? Si la respuesta es no, te falta la mitad del sistema, que es justo lo que construimos nosotros."_

## 5.5 "No sé si lo voy a usar / si me va a funcionar"

**Por qué la dicen:** miedo al cambio o a la inversión sin retorno claro.

**Respuesta:**
> _"Es una preocupación razonable. Por eso trabajamos en sprints cortos: cada 1-2 semanas tenés un avance funcional para revisar. Si en algún momento ves que no es lo que necesitas, lo conversamos y ajustamos antes de que sea tarde. No es 'firmas y desaparezco 3 meses'. Y todos nuestros clientes en producción siguen pagando la mensualidad de soporte porque el sistema entró en su operación diaria — esa es la mejor señal de que sí lo usan."_

## 5.6 "¿Qué pasa si después quiero cambiar de proveedor?"

**Por qué la dicen:** miedo a quedar atrapados (lock-in).

**Respuesta:**
> _"Pregunta muy válida. La respuesta es clara: el código y la base de datos son tuyos. Si en algún momento decidís migrar a otro proveedor o a un equipo interno, te entregamos el código completo, la documentación y los respaldos de datos. No hay candado técnico ni contractual. Construimos sobre tecnologías estándar — Next.js, PostgreSQL — que cualquier desarrollador serio sabe leer."_

## 5.7 "No tengo tiempo ahora / lo veo más adelante"

**Por qué la dicen:** o no es prioridad o es un brush-off educado.

**Respuesta (sondeo):**
> _"Te entiendo. Solo para saber si te queda en el radar: ¿hay algo específico que tendría que pasar para que esto se vuelva prioridad? ¿Volumen, una mudanza, contratar a alguien, fin de año? Así te escribo en el momento correcto y no antes."_

Si responde algo concreto: agéndalo en tu seguimiento y mandá un mensaje útil (sin pitch) para esa fecha.
Si responde vago: ya entendiste que no es lead caliente, despedite con elegancia y movete.

## 5.8 "Necesito pensarlo / consultar con mi pareja/socio"

**Respuesta:**
> _"Por supuesto, decisiones así se conversan. Para que la conversación sea fácil, ¿quieres que te mande un resumen de una página que puedas pasarle directamente? Así no tienes que repetir todo lo que conversamos. ¿Qué dudas crees que va a tener tu [pareja/socio] que pueda anticipar?"_

Esto te da: (1) chance de aterrizar el deal con quien sí decide, (2) lista anticipada de objeciones del decisor real.

# Parte 6 · FAQ del cliente

Respuestas cortas y directas a las preguntas que más reciben.

**¿Cuánto cuesta?**

5. **(5 min)** Siguientes pasos — _"Voy a armar una propuesta con dos opciones de alcance. Te la mando el [día]. ¿Te queda bien?"_

> **Importante:** **NO cotices en la primera reunión**, aunque insistan. Decir _"te paso una propuesta el viernes"_ te da tiempo de estructurar bien y consultar con el equipo técnico.

Una propuesta debe tener:

**Cuando la mandas:**

- Pregunta directo: _"¿qué te tiene dudando?"_
- Si dice _"lo voy a pensar"_, aplica respuesta de objeción 5.8.

**Cuando aceptan:**
- Manda contrato/orden de compra el mismo día.
- Confirma datos de facturación.
- Bloquea fecha de kickoff con el equipo técnico.

## 7.4 Handoff al equipo técnico

Cuando el cliente firma, tu trabajo es entregárselo limpio al dueño / equipo técnico de Gambitho Labs:

1. **Carpeta del cliente** con: propuesta firmada, comprobante del 50% pagado, transcripciones de las reuniones, contactos clave del cliente, integraciones que ya tiene.

2. **Briefing inicial** al dueño técnico con: alcance acordado, expectativas implícitas que detectaste, cosas que el cliente NO dijo pero deberías saber (personalidad, preferencias, urgencias reales).

3. **Reunión de kickoff** entre cliente y dueño técnico, donde tú haces la presentación y luego te quedas en silencio.

# Parte 8 · Glosario rápido

Términos técnicos que vas a escuchar, en lenguaje normal.

| Término | Qué significa en simple |
| --- | --- |
| **PWA** | Una web que se instala como app en el celular sin pasar por la tienda. Más barato y rápido que una app nativa. |
| **Backend** | La parte invisible del sistema: base de datos, servidores, la lógica que hace que todo funcione. |
| **Frontend** | La parte que el usuario ve y toca: pantallas, botones, formularios. |
| **API** | "Enchufe" que permite que dos sistemas hablen entre sí. Por ejemplo, conectar tu web con WhatsApp. |
| **Hosting** | El servidor donde vive el sistema online. Como el alquiler de una oficina, pero virtual. |
| **Dominio** | La dirección web (ej: johannafigueredo.com). Se renueva cada año. |
| **HTTPS / SSL** | Que la conexión es segura y los datos viajan cifrados. Es estándar en cualquier sitio profesional hoy. |
| **Base de datos** | Donde se guardan los datos de forma estructurada. Como un Excel pero para sistemas serios. |
| **Deploy** | "Subir el sistema a internet" para que esté disponible. |
| **CMS** | Panel donde el cliente puede editar contenido (textos, fotos) sin tocar código. |
| **Stack** | El conjunto de tecnologías que usamos: en nuestro caso, Next.js + PostgreSQL. |
| **Sprint** | Período corto (1–2 semanas) donde construimos un avance específico. |
| **Iteración** | Revisar lo construido, ajustar, mejorar. Trabajamos en iteraciones cortas. |
| **Webhook** | Aviso automático que un sistema le manda a otro cuando pasa algo. |
| **Open source** | Tecnología abierta y gratuita, usada por millones de empresas. Lo que usamos nosotros. |
| **Cron job** | Tarea programada que corre sola a una hora específica (ej: mandar recordatorios cada noche a las 8pm). |
